=========================================================
STOWAGE INTELLIGENCE SYSTEM - IMPLEMENTATION & ALGORITHMS
=========================================================

1. OVERVIEW OF ENDPOINTS
------------------------
The Stowage Intelligence service relies on three primary backend endpoints (FastAPI):
- GET  /stowage/history/analysis: Analyzes past vessel visits, computing historical metrics such as weight distribution, deck placements, and crane performance.
- POST /stowage/current/planning: Analyzes a current list of containers (in the yard) and generates a simulated, optimized load plan with sequence steps and yard strategies.
- POST /stowage/visualization: Prepares coordinate mappings (Bay-Row-Tier) to render visual deck/yard maps.

2. DATA INGESTION & NORMALIZATION
---------------------------------
- Data Source: The backend dynamically extracts data using Pandas via SQLAlchemy (see `db/queries.py`). It scans tables dynamically using `pg_class`.
- Deduplication: Because containers create multiple operational events, the backend uses `_dedupe_latest_per_unit` to filter the data down to the most recent state per `unit_id`.
- Current Planning Input: The system accepts `containerIds` via form-data (or a CSV/TXT file) uploaded by the frontend. The `lookup_containers_by_ids` function locates the current yard positions of these containers.

3. HISTORICAL STOWAGE CALCULATIONS (History Analysis)
-----------------------------------------------------
- Weight Banding: Calculated via `classify_weight_band(weight_kg, length)`. 
  * 20ft containers: >20T = HEAVY, <15T = LIGHT, else MEDIUM.
  * 40ft containers: >22.5T = HEAVY, <18T = LIGHT, else MEDIUM.
- Deck Classification: `_determine_historical_deck` evaluates the historical tier. Standard below-deck tiers are 02-18; above-deck tiers are usually 80+.
- Container Breakdown: Aggregates counts for Freight Kind (FCL/MTY/MTL), Size (20ft/40ft), Hazardous Units, Reefers, and Out-of-Gauge (OOG).
- Crane Performance Algorithms: 
  * Reshuffle Rate: Calculates `(UNIT_RESTOW moves / Total Productive Moves) * 100`.
  * Dual Cycle Rate: Tracks consecutive sequences of `UNIT_LOAD` directly followed by `UNIT_DISCHARGE` (or vice versa), allowing the crane to carry a load in both directions. Rate = `(Dual Cycles / Total Productive Moves) * 100`.

4. CURRENT PLANNING & LOAD OPTIMIZATION ALGORITHMS
--------------------------------------------------
- Yard Block Resolution: Extracts the block (e.g., "10" from "Y-PEB-10-A-1-2") using the `ctr_from_position` for loaded units, or `current_position` for yard units.
- Discharge Sequence Calculation (How it determines first vs next port):
  * The system dynamically determines the optimal discharge rotation by calculating container concentration per destination port (`port_of_discharge`).
  * Step 1: It groups all containers for the given vessel (or visit) by their destination port.
  * Step 2: It counts the total volume of containers destined for each port.
  * Step 3: It sorts the ports by volume in descending order. The port with the **highest volume** of containers is assigned `dischargeOrder = 1` (meaning it should be the first port of discharge, so those containers must be loaded LAST / at the top of the stack). 
  * Step 4: The port with the second-highest volume is assigned `dischargeOrder = 2`, and so on.
  * This volume-based sorting acts as a proxy for the vessel's actual rotation, ensuring the terminal doesn't bury massive volumes of containers meant for the primary destination under smaller transshipment clusters.
- Recommendation Algorithm (`generate_recommendation`):
  * Assigns a "Recommended Deck" based on weight (Heavy units prioritize BELOW_DECK, Light units prioritize ABOVE_DECK).
  * Calculates "Reshuffle Risk": Analyzes the yard slot. If a heavy container is buried below lighter containers, the risk is HIGH.
- Yard Strategy Analytics (`process_current_planning_and_yard_strategy`):
  * Proximity Logic: Categorizes yard blocks as CLOSE, MID, or FAR relative to the berth.
  * Pod Concentration Score: Calculates the percentage of containers located in blocks that share the same dominant discharge port.
  * Projected Reshuffle Reduction: Computes `Baseline Reshuffle Rate * Pod Concentration Score`.
  * Insights Generation: Dynamically generates actionable text strings advising yard planners (e.g., "50 HEAVY containers are in berth-close blocks — prioritize for first pick").
